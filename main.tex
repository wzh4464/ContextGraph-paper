\begin{abstract}
Coding agents can repeat costly debugging mistakes even when useful lessons
exist in other repositories. Reusing this experience requires preserving
transferable decisions, connecting related lessons, and retrieving them
when they can guide the next action. We propose ContextGraph, an experience
graph for self-improving coding agents. It abstracts past trajectories into
strategies and warnings linked to their source context, error patterns, and
outcomes. The agent selects guidance using its full context before planning and searches again
after errors to revise its diagnosis. After each task, successful and failed
trajectories contribute new experience that subsequent tasks can immediately
retrieve. ContextGraph achieves resolution rates of 69.2\%, 35.1\%, and
72.1\% on SWE-bench Verified, SWE-ContextBench Related-Lite, and Datacurve
DeepSWE, improving over no memory by 7.6, 4.5, and 11.3 percentage points,
respectively. It leads the evaluated methods on Verified and DeepSWE and
ranks second to Agent KB on Related-Lite. Additional experiments examine
performance across models, memory-pool sizes, and retry budgets. Behavioral
studies expose negative transfer from implementation reuse and show how
composing historical conditions with current operations catches failures
missed by separate checks.
\end{abstract}

\section{Introduction}
\begingroup
\setlength{\parindent}{1em}
\setlength{\parskip}{0pt}
Each repair produces experience in locating faults, revising code, and
checking behavior. Memory reuses this experience on later tasks, offering a
practical route toward recursive self-improvement (RSI)
\citep{godelagent2025,dgm2026}. Both successful and failed attempts contribute.

Related-Lite99 with DeepSeek V4 Pro. Grey denotes no memory and red
ContextGraph.}
\label{fig:results-overview}

Recent agent-memory methods retain reflections and repair lessons
\citep{reflexion2023,expel2024} and organize this experience for reuse
\citep{reasoningbank2026,ace2026}. To transfer across repositories, a lesson
must guide investigation in unfamiliar code and identify approaches to avoid.
The agent then determines the local change. Section~\ref{sec:motivation}
illustrates this transfer to Django from an earlier setup failure and a
successful debugging attempt.

We therefore ask: \emph{Can a memory graph turn experience from different
repositories into useful guidance for planning repairs and recovering from
errors on new tasks?}

Building this memory involves three challenges. First, repair trajectories
contain repository-specific names, code, and setup steps. A transferable
lesson must retain the useful decision and the situation in which it applies.
Removing too little detail ties it to the source repository; removing too
much leaves generic advice. Second, related experiences are scattered across
tasks and repositories. Similar words can describe different problems, while
different errors can call for the same debugging strategy. Retrieval needs
these connections. Third, guidance must change during repair: planning needs
direction for investigation, while errors bring evidence that can change the
diagnosis. Memory must inform both decisions, then retain the completed
attempt for later tasks.

To address these challenges, we propose \textbf{ContextGraph}, a memory graph
that turns experience across repositories into guidance for new repairs
(Figure~\ref{fig:experience-memory}). \emph{Experience abstraction} extracts
strategies and warnings: what to do, what to avoid, and when each lesson
applies. The graph links them to source experiences, problems, and errors.
\emph{Agent-directed selection} uses the full task context to search the
experience pool and follow graph connections, selecting useful strategies
across repositories. \emph{Memory access}
emphasizes two points: before planning and after an error. The first query
uses the available task context; the second adds the error and recent attempt
to guide diagnosis and revision. The agent applies these lessons through
local edits and tests. After every task, ContextGraph distills the successful
or failed trajectory and updates the graph, making new experience immediately
available to subsequent tasks.

ContextGraph reaches 69.2\% resolution on SWE-bench Verified and 72.1\% on
DeepSWE113, exceeding the strongest evaluated memory baselines by 2.2 and
5.9 percentage points, respectively. On Related-Lite99,
its mean resolution rate is 35.1\%, 4.5 points above no memory and second
to Agent KB's 38.2\% (Figure~\ref{fig:benchmark-comparison}).
Figure~\ref{fig:results-overview} previews the benchmark, model, and retry
comparisons. On 20 Python tasks
from LoLBench, ContextGraph reaches 15.0\% pass@1 versus 5.0\% for all
baselines, and 25.0\% pass@3.

\noindent The contributions are summarized as follows:
\begin{itemize}
\item We propose ContextGraph, a memory graph for reusing coding experience
across repositories. It connects abstract strategies and warnings to the
problems, errors, and outcomes that explain when the guidance is useful.
\item We integrate memory retrieval into planning and error recovery.
The full task context guides memory selection; observed failures guide
subsequent searches. Successful and failed trajectories update the graph after each
task, connecting current repair decisions to continuing experience accumulation.
\item ContextGraph leads the evaluated methods on SWE-bench Verified,
DeepSWE113, and the LoLBench Python subset, and improves Related-Lite99 by
4.5 points over no memory. Behavioral studies identify negative transfer
from implementation reuse and show the benefit of checking historical
conditions within current operations.
\end{itemize}

\section{Experiments}
\label{sec:experiments}
\label{sec:recorded-results}
We ask whether ContextGraph improves repair success, how its benefits vary
across models and memory-pool sizes, whether memory reduces repeated repair
effort, and how retrieved experience changes an agent's actions.

\subsection{Setup and evaluation}
\label{sec:setup}
\paragraph{Tasks and metrics.}
We evaluate all 500 SWE-bench Verified tasks, the 99-task Related-Lite subset
of SWE-ContextBench, and the 113-task Datacurve DeepSWE benchmark
\citep{swebench2024,swecontext2026,deepswe2026}. We additionally evaluate
20 Python tasks from LoLBench \citep{lolbench2026}. A task is resolved when
its patch passes the benchmark's official evaluation. Resolution is the
percentage of tasks resolved; pass@$k$ reports success within $k$ attempts.
Related-Lite99 and DeepSWE113 in the main comparison report means over five
runs, each reset to the same initial memory pool. Tasks are evaluated in
issue creation-time order. Table~\ref{tab:evaluation-settings} summarizes the main settings.

\paragraph{Agents and memory.}
Table~\ref{tab:evaluation-settings} gives the models, agents, and initial
memory sources \citep{minisweagent2025,sweagent2024}. ContextGraph adds
experience from every successful or failed task for immediate subsequent use.
Baselines follow their open-source update defaults. The comparisons evaluate
memory construction, selection, and updating as a complete system.

\paragraph{Data separation and feedback.}
Initial memory excludes the evaluated tasks' trajectories and reference
solutions, and development tasks do not overlap the test sets. Tasks enter
the evaluation stream in issue creation-time order. Memory updates use only
agent-visible actions and observations, including its own test runs. Official
test results are used for scoring only: they are neither shown to the agent
nor written into memory, including between repeated attempts.

\paragraph{Baselines.}
We compare no memory, FAISS Flat, ExpeL, Agent KB, ExpeRepair, ReasoningBank,
ACE, and Supermemory \citep{expel2024,agentkb2025,experepair2026,
reasoningbank2026,ace2026,supermemoryreport2026}. FAISS Flat uses vector
similarity to retrieve memory without graph traversal. We adapt ExpeRepair
and ACE to mini-SWE-agent, retaining their memory procedures. Supplementary
model, pool-size, and retry comparisons state their own inputs and budgets
alongside the results. Appendix Table~\ref{tab:main-results-overview} lists all
main comparison values.

\subsection{Repair effectiveness}
\label{sec:benchmark}
\label{sec:recorded-effectiveness}
Figure~\ref{fig:benchmark-comparison} compares nine methods. ContextGraph
reaches 69.2\% on Verified500 and 72.1\% on DeepSWE113, exceeding the strongest
memory baselines, ReasoningBank and Supermemory, by 2.2 and 5.9 points.
On Related-Lite99, its 35.1\% mean improves on no memory and FAISS Flat by
4.5 and 8.3 points; Agent KB leads at 38.2\%.
\textbf{Finding:} ContextGraph improves repair success on all three
benchmarks, leading the evaluated methods on Verified500 and DeepSWE113.

\paragraph{Long-horizon development.}
With Codex and GPT-5.5, we build the graph from other Python tasks and evaluate
20 LoLBench tasks. All seven memory baselines match no memory at

(Appendix Table~\ref{tab:new-codex55}).
\textbf{Finding:} ContextGraph achieves the highest pass@1 among the evaluated
methods on this 20-task long-horizon subset.

\subsection{Performance across models and memory-pool sizes}
\label{sec:generalization}
\label{sec:recorded-generalization}
\paragraph{Benefits across language models.}
In the Related-Lite99 single-attempt comparison, memory methods draw from the
same 300-summary pool within each model (Figure~\ref{fig:swectx-crossmodel}),
including Mem0 \citep{mem02025} and LangMem \citep{langmem2025}.
With DeepSeek V4 Pro, ContextGraph reaches 35.1\% resolution, compared with
30.6\% without memory. The oracle is given one known related summary, bypassing
retrieval; ContextGraph can retrieve several.
\textbf{Finding:} memory reuse improves resolution with all three models, with the
highest non-oracle resolution rate in each model comparison.

\paragraph{Pool size and source coverage.}
With the DeepSeek V4 Pro agent and retrieval procedure fixed, the 300-summary pool
produces the highest resolution rate, 35.1\%
(Table~\ref{tab:swectx-poolsize}). Source coverage measures the proportion
of oracle-designated relevant sources recovered by retrieval. It rises from
41.3\% to 60.7\% as the pool grows from 50 to 300 summaries, while resolution
does not improve at every intermediate step.
\textbf{Finding:} larger pools recover more oracle-designated sources, and
the largest tested pool yields the strongest repair result.

\subsection{Repair success with repeated attempts}
\label{sec:retries}
A separate Related-Lite99 experiment uses DeepSeek V4 Pro with 500 calls and
\$30 per task in both conditions. The memory contains 291 curated repair
records with reference fixes, verification hints, and history preceding the
target code version. Each pass is a repair round; later passes retry only
unresolved tasks. ContextGraph reaches 25 resolutions
in two passes; the no-memory agent needs three
(Table~\ref{tab:swectx-stream}). Excluding ten targets with near-duplicate source
fixes retains the first-pass gain, 19/89 versus 13/89 ($p=.031$).
\textbf{Finding:} useful experience helps the agent reach successful repairs
with fewer rounds, with the largest gains in the first two passes.

\subsection{What should memory preserve and help the agent check?}
\label{sec:behavior-analysis}
The example in Section~\ref{sec:motivation} shows how abstract experience
guides investigation. Here we study how an agent applies a remembered
requirement: pairing it with executable checks and combining historical
conditions with the current operation (Figure~\ref{fig:concept}).
Table~\ref{tab:condition-findings} summarizes two findings;
Appendix~\ref{sec:evidence} gives the full studies.


\paragraph{Preserve the requirement without inheriting an unsuitable implementation.}
In the timezone study, requirement-level memory passes all 72 combinations
of database, application, and output zones. Reusing the historical
implementation passes 40 and breaks 16 combinations that pass without memory.
The requirement identifies the behavior to preserve; the implementation
carries assumptions that fail in the new setting, causing negative transfer.

\paragraph{Check historical conditions together with the current operation.}
For Django12663, three agents receive the same task, history, current program,
tools, and repair budget. They receive current feedback alone, additional
separate historical checks, or additional composed checks. All three repairs
pass official verification. Both added-check conditions recover the two
historical examples, but their joint behavior differs: separate checks pass
only one of three withheld joint queries, while composed checks pass all three.
The current-feedback repair passes two. The interaction becomes visible when
the historical input condition is exercised inside the current operation.
\textbf{Finding:} memory should preserve the conditions under which a lesson
applies. Turning those conditions into checks in the current workflow can
expose failures that separately passing examples miss.

\section{Conclusion}
ContextGraph connects transferable strategies and warnings to their source
experience. Agents use their full context to select guidance before planning
and after errors, then contribute new experience after each task. With
DeepSeek V4 Pro, it achieves 69.2\%, 35.1\%, and 72.1\% resolution on
Verified500, Related-Lite99, and DeepSWE113. Gemini 3.1 Pro reaches 88.9\%
pass@1 on Verified500, while LoLBench pass@1 improves from 5.0\% to 15.0\%.
These results establish experience graphs as a strong starting point for
self-improving coding-agent memory.

\section*{Limitations}
The main comparisons measure the full memory systems; their aggregate gains
combine representation, retrieval, and updating. Behavioral cases explain
specific repair decisions, while the 20-task LoLBench study covers one
language and a small part of that benchmark. Broader task streams and
controlled component comparisons would clarify when each design contributes
most. Detailed settings and additional results accompany the appendices.
