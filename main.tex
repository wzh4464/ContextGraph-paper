\begin{abstract}
Coding agents repeat costly debugging mistakes even when a lesson that would
avoid them was learned on an earlier task, often in another repository. We
study what makes experience memory help such agents, using ContextGraph, an
experience graph that distills successful and failed trajectories into
strategies and warnings with the conditions under which they apply, lets the
agent select them with its full context before planning and after errors,
and adds every completed task back to memory. ContextGraph improves over no
memory by 7.6, 13.7, and 11.3 points on SWE-bench Verified, SWE-ContextBench
Related-Lite, and Datacurve DeepSWE, reaching 69.2\%, 35.1\%, and 72.1\%, the
highest rate among the evaluated memory methods on each. Its ablations show
that two choices are prerequisites for the gain: memory should store abstract
lessons and let the agent select them for each task. On Related-Lite, raw
trajectory excerpts selected by the agent and a fixed set of abstract lessons
given to every task both stay at the no-memory level (20.5\% and 20.8\%
versus 21.4\%), and abstract lessons retrieved by embedding similarity leave
ContextGraph only 2.9 of its 13.7 points. Updating memory after every task
adds further gains, and lessons from other repositories alone carry more than
half of the gain on Related-Lite and DeepSWE. The gains hold for
strong agents: with Gemini 3.1 Pro, one attempt with memory resolves 88.9\%
of SWE-bench Verified, above the 82.8\% that five attempts reach without it.
We release the code and prompts so that others can build on these findings.
\end{abstract}

Each repair a coding agent attempts produces experience: where the fault
was, which reproduction exposed it, and which approach wasted effort. Memory
lets later tasks reuse this experience, so the agent improves from its own
work without changing its weights or code, unlike agents that rewrite
themselves \citep{godelagent2025,dgm2026}. Memory methods differ in what
they store (trajectories, insights, or playbook entries), how a task receives
it (similarity top-$k$ or the whole playbook), and whether memory changes
during use \citep{reflexion2023,expel2024,reasoningbank2026,ace2026}
(Table~\ref{tab:positioning}). These choices matter: under a shared agent,
backbone, and budget, six memory systems change resolution by between
$-2.1$ and $+9.9$ points over no memory (Section~\ref{sec:benchmark}). We ask
which choices make experience memory work for coding agents;
Figure~\ref{fig:teaser} previews the answer.

Figure~\ref{fig:concept} shows what a useful memory holds. In Django Trac
\#33018, empty query results are mishandled under negation. A failed
\texttt{python-statemachine} attempt had spent its effort setting up a full
Django application, and a successful \texttt{sievelib} trajectory supported
reproducing the failure before editing. From these two attempts, the agent selected a
strategy (reproduce the failure in a minimal script), a warning (do not set
up the full framework first), and the condition under which both apply (the
failure appears without the full application). Guided by them, it traced the
fault to \texttt{Exists.as\_sql()}, corrected its handling, and added a
regression test; the no-memory attempt made broad formatting changes without
fixing the bug. Neither source repository is Django: the decision and its
condition transferred, and the agent wrote the local fix.

We answer this question with \textbf{ContextGraph}
(Section~\ref{sec:method}), whose five design choices can each be switched
off and measured. It distills
successful and failed trajectories into strategies and warnings with the
conditions under which they apply, links them to their source experience and
the errors they address, lets the agent select lessons with its full context
before planning and again after errors, and distills every completed task
back into memory. Across four benchmarks, five backbones, and three agent
scaffolds, ContextGraph improves repair. With DeepSeek V4 Pro it improves over
no memory by 7.6, 13.7, and 11.3 points on SWE-bench Verified,
SWE-ContextBench Related-Lite, and Datacurve DeepSWE, the largest gain among
the evaluated memory methods on each; with Gemini 3.1 Pro it raises Verified
pass@1 from 82.3\% to 88.9\%; and with GPT-5.5 in Codex it solves 15.0\% of
20 long-horizon LoLBench Python tasks at pass@1, where no memory and six
memory baselines solve 5.0\%. Its ablations and analyses yield five takeaways for
building coding-agent memory:

\smallskip
\noindent\fbox{\begin{minipage}{\dimexpr\linewidth-2\fboxsep-2\fboxrule\relax}\small
\textbf{What works for coding-agent memory.} Takeaways 1 and 2 are
prerequisites: removing either leaves ContextGraph at most 2.9 of its 13.7
points (Figure~\ref{fig:teaser}). Takeaways 3--5 show what else the gain
draws on and where it holds.
\begin{enumerate}\setlength{\itemsep}{1pt}\setlength{\topsep}{2pt}\setlength{\parsep}{0pt}
\item \textbf{Abstract experience into lessons; do not replay trajectories.}
Raw trajectory excerpts stay at the no-memory level even when the agent
selects them for each task (Section~\ref{sec:ablation}).
\item \textbf{Match lessons to each task, and let the agent choose them.}
A fixed playbook on every task gives no gain; agent-directed selection beats
similarity top-$k$ by 10.8 points and random summaries from the same pool by
8.0 (Section~\ref{sec:selection}).
\item \textbf{Update memory after every task.} Online updates add 6.4 points
over a static pool, and their lead grows along the task stream and across
retries (Section~\ref{sec:stream}).
\item \textbf{Share experience across repositories, and collect enough of
it.} Lessons from other repositories alone carry more than half of the gain
on two benchmarks; 50 initial summaries give no gain, 300 give the full 13.7
points (Section~\ref{sec:cross-repo}).
\item \textbf{Use memory with strong agents too.} With Gemini 3.1 Pro, one
attempt with memory resolves more Verified tasks than five without, and
with GPT-5.5 in Codex ContextGraph solves 15.0\% of 20 LoLBench Python tasks
at pass@1, where every other method solves 5.0\% (Section~\ref{sec:backbones}).
\end{enumerate}
\end{minipage}}

These findings extend the abstraction and pool-size effects of Memory
Transfer Learning \citep{transfer2026} to repository-level repair, and bring
condition-structured lessons \citep{clin2023,autoguide2024} to coding agents. We contribute ContextGraph, an experience graph that
integrates memory into planning, error recovery, and learning after every
task; the five takeaways, each backed by controlled ablations or analyses in
Section~\ref{sec:experiments}; and the code, prompts, and graph schema,
released so that others can build on them.

\section{What works for coding-agent memory}
\label{sec:experiments}
\label{sec:recorded-results}

\subsection{Setup}
\label{sec:setup}
\paragraph{Tasks and metrics.}
We evaluate all 500 SWE-bench Verified tasks (Verified500), the 99-task
Related-Lite subset of SWE-ContextBench (Related-Lite99), and the 113-task
Datacurve DeepSWE benchmark (DeepSWE113)
\citep{swebench2024,swecontext2026,deepswe2026} with DeepSeek V4 Pro 0813
and mini-SWE-agent \citep{minisweagent2025,sweagent2024}, and 20 Python tasks
from LoLBench \citep{lolbench2026} with GPT-5.5 and Codex. Their initial
memory comes from Nebius SWE-bench-extra trajectories, SWE-bench cold-start
trajectories, LoLBench repository trajectories, and other LoLBench Python
tasks, respectively (Appendix Table~\ref{tab:evaluation-settings}). A task is resolved when
its patch passes the benchmark's official evaluation. Resolution is the
percentage of tasks resolved over completed evaluations; pass@$k$ reports
success within $k$ attempts; Appendix~\ref{sec:uncertainty} gives confidence
intervals. Related-Lite99 and DeepSWE113 in the main comparison report means
over five runs, each reset to the same initial memory pool. All methods share
the agent, backbone, and a per-task budget of 500 steps and \$20 on
Verified500 and Related-Lite99, \$50 on DeepSWE113, and \$100 on LoLBench;
ContextGraph distills lessons with Claude 4 Sonnet.

\paragraph{Data separation and feedback.}
Initial memory excludes the evaluated tasks' trajectories and reference
solutions; one instance-level and patch-similarity audit is applied to
every pool of the main comparison (Appendix~\ref{sec:overlap-audit}). Tasks
enter the evaluation stream in issue creation-time order, and ContextGraph's
memory grows task by task on every benchmark, including Related-Lite99, whose original
protocol keeps its pool fixed \citep{swecontext2026}. Memory updates use only
agent-visible actions and observations, including the agent's own test runs.
Official test results are never shown to the agent or written into memory;
beyond scoring, they only decide which tasks the retry experiment of
Section~\ref{sec:stream} attempts again. Code, extraction prompts, and the
graph schema are released in an anonymous
repository.\footnote{\url{https://anonymous.4open.science/r/contextgraph-kit/}}

\paragraph{Baselines.}
We compare no memory, FAISS Flat, ExpeL, ExpeRepair, ReasoningBank,
ACE, and Supermemory \citep{expel2024,experepair2026,
reasoningbank2026,ace2026,supermemoryreport2026}. FAISS Flat uses vector
similarity to retrieve memory without graph traversal. We adapt ExpeRepair
and ACE to mini-SWE-agent, retaining their memory procedures. Each baseline
is a complete memory system with its own construction, selection, and
updates; the ablations that follow isolate individual choices. Appendix
Table~\ref{tab:main-results-overview} lists all values.

\subsection{ContextGraph improves repair on every benchmark}
\label{sec:benchmark}
\label{sec:recorded-effectiveness}
Figure~\ref{fig:benchmark-comparison} shows each memory method's gain over no
memory. ContextGraph improves by 7.6, 13.7, and 11.3 points on Verified500,
Related-Lite99, and DeepSWE113, reaching 69.2\%, 35.1\%, and 72.1\%, the
highest rate on each. Averaged over the three benchmarks, its gain of 10.9
points is more than twice that of the strongest baseline, ExpeRepair (5.2),
while ExpeL falls below no memory on two of the three. The following
subsections give one takeaway each.

\subsection{Abstract experience into lessons; do not replay trajectories}
\label{sec:ablation}
Table~\ref{tab:ablation} changes one component at a time on Related-Lite99
under the main protocol and keeps the others unchanged, except in the static
playbook, which has no memory access at all. \emph{Raw
trajectories} skips abstraction and stores trajectory excerpts instead of
strategies and warnings; the agent still selects them with its full context.
This erases the entire gain: 20.5\% against 21.4\% without memory and 35.1\%
for the full system (Figure~\ref{fig:teaser}); this drop and the static
playbook's both exceed their conservative 95\% half-widths (Appendix
Table~\ref{tab:uncertainty}). SWE-ContextBench shows the same contrast for
supplied history with Claude Sonnet 4.5: supplying the known related
trajectory adds 1.01 points, whereas supplying a summary of it adds 8.08
(Appendix Table~\ref{tab:published-swectx-lite}). Most lessons the agent
selects come from other repositories (Section~\ref{sec:cross-repo}). An
excerpt from another repository carries that repository's code; an abstract
lesson carries the decision and the condition under which it applies, and
the agent writes the local change.

\subsection{Match lessons to each task, and let the agent choose them}
\label{sec:selection}
Abstract lessons still have to reach the right task. The \emph{static
playbook} places the lessons the agent selects most often in the system
prompt of every task, with no memory access at all, and stays at the
no-memory level (20.8\%): even these lessons do not help when every task
receives the same fixed set. ACE, which also gives every task its whole
playbook but updates it online, reaches 28.1\%. With the same abstract
lessons in memory, resolution rises as the agent takes over the choice of
lessons: \emph{fixed top-$k$}, which retrieves the $k$ lessons most similar
by embedding, reaches 24.3\%; agent-directed search over a flat pool without
graph links, 31.1\%; and search that also follows graph links, 35.1\%.
ReasoningBank, which also retrieves abstract strategies by top-$k$
similarity, reaches a similar 24.9\%, and FAISS Flat, which retrieves by
vector similarity, 26.8\%. With DeepSeek V4 Pro, ContextGraph exceeds random
summaries from the same 300-summary pool by 8.0 points (35.1\% against
27.1\%), and with all three backbones of Figure~\ref{fig:swectx-crossmodel}
it exceeds an oracle that is handed one known related summary (35.1\%,
28.6\%, and 27.6\% against 27.8\%, 24.5\%, and 15.8\%).

\paragraph{The choices work together.} Removing abstraction, agent-directed
selection, online updates, graph links, or search after errors one at a time
costs 14.6, 10.8, 6.4, 4.0, and 1.9 points: 37.7 in total, 2.75 times the
13.7-point gain. Abstraction and agent-directed selection are prerequisites:
removing either leaves ContextGraph at most 2.9 of its 13.7 points. Without
abstraction, the other four choices together add nothing (20.5\%); without
agent-directed selection, they add 2.9 points (24.3\%).

\subsection{Update memory after every task}
\label{sec:stream}
\label{sec:retries}
Online updates add 6.4 points (Table~\ref{tab:ablation}); even without them,
ContextGraph (28.7\%) stays 8.0 points above ExpeL (20.7\%), which also
keeps a static pool. A separate retry study on Related-Lite99 shows
how the benefit of updating builds up (Table~\ref{tab:stream-position}). It
uses DeepSeek V4 Pro with the main-comparison budget, a curated pool of 291
repair records of other tasks with their reference fixes and verification
hints, and three settings, all run within the study:
no memory, a static pool, and online updates. Each later pass retries the tasks
that remain unresolved. Online updates and the static pool start from the
same pool, so their difference isolates what the agent learns during the run.
They match in the first third of the stream (5.4 versus 5.6 of 33 tasks);
the lead of online updates then grows to 1.0 and 3.0 tasks, while no memory
stays flat (4.6, 4.8, 4.8). Retries compound the benefit, and with online
updates a retry can draw on lessons distilled during the run, including from
the task's own failed attempt: two
retry passes add 5.4 tasks with online updates, 2.8 with the static pool, and
2.0 without memory, and one pass with online updates (21.2 tasks) already
resolves more than three passes with the static pool (20.2). Sequential
attempts behave the same way with Gemini 3.1 Pro on Verified500: with memory
updated after each attempt, pass@5 adds 2.8 points over pass@1, against 0.5
without memory (Appendix Table~\ref{tab:new-gemini}).

We log the source repository of every lesson selected in the main comparison
(Table~\ref{tab:cross-repo}): 78.4\%, 86.2\%, and 64.1\% come from another
repository on Verified500, Related-Lite99, and DeepSWE113. With
same-repository lessons excluded at selection time, ContextGraph still
improves over no memory by 1.4, 7.3, and 6.7 points, more than half of the
full gain on Related-Lite99 and DeepSWE113. The repository's own lessons add
the rest (6.2, 6.4, and 4.6 points), which on Verified500 is most of the gain. The
DeepSWE113 initial pool contains no DeepSWE113 repository
(Appendix~\ref{sec:overlap-audit}), so its same-repository lessons were all
learned online from earlier tasks in the stream: updating memory is how a new
repository acquires its own experience. The amount of experience matters as
well. The Related-Lite99 initial pool holds 300 experience summaries distilled
from its audited SWE-bench cold-start trajectories
(Appendix~\ref{sec:historical}); with the
agent and selection procedure fixed, resolution rises from 20.2\% to 26.3\%,
28.3\%, and 35.1\% as the pool grows from 50 to 100, 200, and 300 summaries
(single runs for 50--200; the 300-summary value is the five-run mean of the
main comparison). Fifty summaries do not yet help; each larger pool resolves
more.

\subsection{Use memory with strong agents too}
\label{sec:backbones}
With Gemini 3.1 Pro and live-SWE-agent on Verified500, ContextGraph raises
pass@1 from 82.3\% to 88.9\% and pass@5 from 82.8\% to 91.7\% (Appendix
Table~\ref{tab:new-gemini}): one attempt with memory resolves more tasks than
five without, and memory removes 37\% of the failures that remain without it
at pass@1 and 52\% at pass@5. On 20 long-horizon LoLBench tasks with Codex
and GPT-5.5, and a graph built from other Python tasks, ContextGraph solves 3
tasks at pass@1 (15.0\%), while no memory and each of the six memory
baselines solve 1 (5.0\%); with three attempts, it solves 5 (25.0\%; Appendix
Table~\ref{tab:new-codex55}). The gain also holds across backbones on
Related-Lite99, where the memory methods of
Figure~\ref{fig:swectx-crossmodel}, including Mem0 \citep{mem02025} and
LangMem \citep{langmem2025}, draw from the same 300-summary pool within each
backbone: ContextGraph improves over no memory by 13.7, 10.0, and 8.2 points
with DeepSeek V4 Pro, Kimi K3, and MiniMax M2.7 and has the highest rate with
each; with DeepSeek V4 Pro, LangMem
comes closest, 1.1 points behind. Memory also saves tokens: on
Verified500 with DeepSeek V4 Pro, ContextGraph uses 201K tokens per task
against 236K without memory, 14.8\% fewer.

\section{Conclusion}
We asked what makes experience memory work for coding agents. ContextGraph's
ablations and its results on four benchmarks with five backbones give a
clear answer. Memory helps most when it stores abstract lessons rather than
trajectories and lets the agent select them for each task; removing either
from ContextGraph leaves at most 2.9 of its 13.7 points on Related-Lite99. On
that foundation, updating memory after every task adds further gains. Lessons
from other repositories alone carry more than half of the gain on
Related-Lite99 and DeepSWE113, and the gain grows with the amount of
experience. The gains hold for strong agents: with Gemini 3.1 Pro, one
attempt with memory resolves more tasks than five without. We release the
code, prompts, and graph schema so that others can build on these findings.

\section*{Limitations}
Our ablations remove abstraction together with the rest of the lesson format;
a variant that keeps agent-directed selection but strips only the
applicability condition would pin down the condition's share. A retry control in which a no-memory agent reflects on its own failures
\citep{reflexion2023}, longer task streams, and more languages and agent
scaffolds are natural next steps.

\section*{Reproducibility statement}

experience-graph implementation used in our experiments
(\texttt{research/}) with its extraction prompts and graph schema, the
scripts and data that generate the figures (\texttt{research/figures}), and
