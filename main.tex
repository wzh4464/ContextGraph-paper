\begin{abstract}
Coding agents can repeat costly debugging mistakes even when useful lessons
exist in other repositories. Reusing this experience requires preserving
transferable decisions, connecting related lessons, and retrieving them
when they can guide the next action. We propose ContextGraph, an experience
graph for self-improving coding agents. It distills strategies and warnings
together with their applicability conditions and intended outcomes, retaining
links to the source experience. The agent selects guidance using its full
context before planning and searches again after errors to revise its
diagnosis. After each task, successful and failed trajectories contribute new
experience that subsequent tasks can immediately retrieve. ContextGraph
achieves resolution rates of 69.2\%, 35.1\%, and 72.1\% on SWE-bench
Verified, SWE-ContextBench Related-Lite, and Datacurve DeepSWE, improving over
no memory by 7.6, 13.7, and 11.3 percentage points and reaching the highest
rate among the evaluated memory methods on each. With Gemini 3.1 Pro, it
raises Verified pass@1 from 82.3\% to 88.9\%. Ablations point to a simple
recipe for coding-agent memory: store abstract lessons rather than raw
trajectories, and match each lesson to the condition under which it applies.
Raw trajectories and a fixed playbook of the same lessons both stay at the
no-memory level, while condition-matched lessons add 13.7 points. We release
the code, prompts, and memory pools so that others can build on these
findings.
\end{abstract}

\section{Introduction}
\begingroup
\setlength{\parindent}{1em}
\setlength{\parskip}{0pt}
Each repair produces experience in locating faults, revising code, and
checking behavior. Memory reuses this experience on later tasks, offering a
practical route toward recursive self-improvement (RSI)
\citep{godelagent2025,dgm2026}. Both successful and failed attempts contribute.

Recent agent-memory methods retain reflections and repair lessons
\citep{reflexion2023,expel2024} and organize this experience for reuse
\citep{reasoningbank2026,ace2026}. To transfer across repositories, a lesson
must guide investigation in unfamiliar code and identify approaches to avoid.
The agent then determines the local change. Section~\ref{sec:motivation}
illustrates this transfer to Django from an earlier setup failure and a
successful debugging attempt in two other repositories.

We therefore ask: \emph{How can coding-agent memory preserve the conditions
behind a useful decision and help an agent adapt that decision to unfamiliar code?}
Our central idea is to remember when a lesson applies and what behavior it
should preserve, so the agent can adapt it to the current task.

Building this memory involves three challenges. First, a lesson must retain
the useful decision and its applicability conditions while abstracting away
repository-specific names and code. Second, related experiences are scattered
across repositories: similar words can describe different problems, while
different errors can call for the same strategy. Retrieval needs these
connections. Third, planning needs direction for investigation, while errors
bring evidence that can change the diagnosis. Memory must inform both
decisions, then retain the completed attempt for later tasks.

To address these challenges, we propose \textbf{ContextGraph}, a memory graph
that turns experience across repositories into guidance for new repairs
(Figure~\ref{fig:experience-memory}). \emph{Experience abstraction} extracts
strategies and warnings: what to do, what to avoid, and when each lesson
applies. The graph links them to source experiences, problems, and errors.
\emph{Agent-directed selection} uses the full task context to search the
experience pool and follow graph connections, selecting useful strategies
across repositories. \emph{Memory access}
emphasizes two points: before planning and after an error. The first query
uses the available task context; the second adds the error and recent attempt
to guide diagnosis and revision. The agent applies these lessons through
local edits and tests. After every task, ContextGraph distills the successful
or failed trajectory and updates the graph, making new experience immediately
available to subsequent tasks.

Building on evidence that abstract memories transfer across coding domains
\citep{transfer2026} and on agents that store condition-structured lessons
\citep{clin2023,autoguide2024}, we find that for repository-level repair the
condition is what makes a lesson useful. Raw trajectory excerpts and a fixed
playbook of the most frequently selected lessons both stay at the no-memory
level on Related-Lite99 (20.5\% and 20.8\% versus 21.4\%), whereas lessons
matched to their conditions reach 35.1\% (Section~\ref{sec:ablation}).

\noindent The contributions are summarized as follows:
\begin{itemize}
\item We propose ContextGraph, a memory graph for reusing coding experience
across repositories. It connects abstract strategies and warnings to the
problems, errors, and outcomes that explain when the guidance is useful, and
integrates retrieval into planning and error recovery.
\item We identify what makes coding-agent memory work: abstraction and
condition matching. Without either, memory does not help; with both, it adds
13.7 points on Related-Lite99.
\item ContextGraph improves over no memory by 7.6, 13.7, and 11.3 points on
Verified500, Related-Lite99, and DeepSWE113, reaches the highest rate among
the evaluated memory methods on each, and with Gemini 3.1 Pro raises Verified
pass@1 from 82.3\% to 88.9\%. We release the code, prompts, and memory pools.
\end{itemize}

\section{Experiments}
\label{sec:experiments}
\label{sec:recorded-results}
We ask whether ContextGraph improves repair success, which components
contribute, how the online loop changes later tasks, what cross-repository
experience contributes, and how benefits vary across models and pool
sizes.

\paragraph{Data separation and feedback.}
Initial memory excludes the evaluated tasks' trajectories and reference
solutions. The Nebius SWE-bench-extra trajectories that seed the Verified500
pool contain none of the 500 evaluated instances, and the same instance-level
and patch-similarity audit is applied to every pool of the main comparison
(Appendix~\ref{sec:overlap-audit}). Related-Lite99 follows the
SWE-ContextBench protocol \citep{swecontext2026}: memory starts from a
cold-start pool of SWE-bench trajectories and grows task by task. Tasks enter
the evaluation stream in issue creation-time order. Memory updates use only
agent-visible actions and observations, including its own test runs. Official
test results are used for scoring only: they are neither shown to the agent
nor written into memory, including between repeated attempts.
Code, extraction prompts, graph schema, initial pools, and evaluation scripts
are released in an anonymous repository.\footnote{\url{https://anonymous.4open.science/r/contextgraph-kit/}}

\paragraph{Baselines.}
We compare no memory, FAISS Flat, ExpeL, ExpeRepair, ReasoningBank,
ACE, and Supermemory \citep{expel2024,experepair2026,
reasoningbank2026,ace2026,supermemoryreport2026}. FAISS Flat uses vector
similarity to retrieve memory without graph traversal. We adapt ExpeRepair
and ACE to mini-SWE-agent, retaining their memory procedures. We compare complete memory systems, including their
construction, selection, and updates. Appendix Table~\ref{tab:main-results-overview}
lists all main comparison values.

\subsection{Repair effectiveness}
\label{sec:benchmark}
\label{sec:recorded-effectiveness}

improves over no memory by 7.6, 13.7, and 11.3 points on Verified500,

\textbf{Finding:} condition-matched experience memory improves repair on all

\paragraph{Benefits with Gemini and live-SWE-agent.}
With Gemini 3.1 Pro and live-SWE-agent, ContextGraph raises Verified500
pass@1 from 82.3\% to 88.9\% and pass@5 from 82.8\% to 91.7\%
(Appendix Table~\ref{tab:new-gemini}). Without memory, extra attempts add
less than one point; with memory updated after every attempt, pass@$k$ keeps
rising as later attempts draw on lessons distilled from earlier ones.
On Verified500 with DeepSeek V4 Pro, ContextGraph also uses fewer tokens per
task, 201K versus 236K without memory, a 14.8\% reduction.

\paragraph{Long-horizon development.}
With Codex and GPT-5.5, we build the graph from other Python tasks and evaluate
20 LoLBench tasks. All six memory baselines match no memory at
5.0\% pass@1; ContextGraph reaches 15.0\% pass@1 and 25.0\% pass@3
(Appendix Table~\ref{tab:new-codex55}), an encouraging sign that the same
memory helps on long-horizon development.

\subsection{Which components contribute?}
\label{sec:ablation}
Table~\ref{tab:ablation} removes one component at a time on Related-Lite99
under the main protocol. \emph{Fixed top-$k$} replaces agent-directed
selection with the $k$ most similar lessons by embedding. \emph{No graph
links} keeps agent-directed search but over a flat pool of lessons without
the relations in Equation~\ref{eq:experience-graph}. \emph{Raw trajectories}
skips abstraction and stores trajectory excerpts instead of strategies and
warnings. \emph{Planning-time only} disables the search after errors.
\emph{Static pool} disables updates during evaluation. \emph{Static playbook}
places the most frequently selected lessons in the system prompt of every
task without memory access, testing whether the gain comes from generic
advice. Each variant keeps the remaining components unchanged.

Two variants show what makes memory useful. \emph{Raw trajectories} keeps
the code and drops the abstraction; the \emph{static playbook} keeps the most
useful lessons but applies them to every task regardless of their conditions.
Both stay at the no-memory level (20.5 and 20.8 versus 21.4), whereas
condition-matched lessons reach 35.1. Agent-directed selection contributes
10.8 points over fixed top-$k$ retrieval, online updates 6.4, graph links
4.0, and search after errors 1.9. Even with updates disabled, ContextGraph
(28.7\%) stays well above ExpeL (20.7\%), which also uses a fixed pool.
\textbf{Finding:} abstract the lesson and match it to its condition; letting
the agent select from the graph, updating it online, and searching again
after errors each add further gains.

\subsection{Self-evolution along the task stream}
\label{sec:stream}
\label{sec:retries}
Because every completed task is distilled into memory
(Section~\ref{sec:experience-access}), later tasks and retries can draw on
lessons from earlier attempts in the same run. Under the main protocol,
freezing the pool costs 6.4 points (Table~\ref{tab:ablation}). A retry
experiment on Related-Lite99 shows how this benefit builds up along the
stream. It uses DeepSeek V4 Pro with 500 calls and \$30 per task, a curated
pool of 291 repair records with reference fixes and verification hints, and
three conditions: no memory, a static pool, and online updates
(Table~\ref{tab:stream-position}; per-pass counts in
Appendix Table~\ref{tab:swectx-stream}).

\paragraph{First pass by stream position.}
Online updates and the static pool start from the same curated pool, so
their difference isolates what the agent learns during the run. In the first
third of the stream, the two match (5.4 versus 5.6 of 33); in the last third,
online updates resolve 8.6 against 5.6, while no memory stays flat (4.6, 4.8,
4.8). The gain over no memory also holds after excluding ten targets with
near-duplicate source fixes, 19/89 versus 13/89 ($p=.031$).

\paragraph{Retry passes.}
After three passes, online updates resolve 26.6 tasks, the static pool 20.2,
and no memory 16.2. Without memory, the third pass adds nothing; with online
updates, each pass keeps converting earlier failures into repairs.
\textbf{Finding:} the benefit of online updates grows along the task stream
and across retries: memory that keeps learning outperforms a fixed pool.

\subsection{Cross-repository transfer}
\label{sec:cross-repo}
The Django example in Section~\ref{sec:motivation} drew on two other
repositories. We log the source repository of every lesson selected in the
main comparison (Table~\ref{tab:cross-repo}): 78.4\% on Verified500, 86.2\% on
Related-Lite99, and 64.1\% on DeepSWE113 come from other repositories. The
DeepSWE113 initial pool contains no DeepSWE113 repository
(Appendix~\ref{sec:overlap-audit}), so its same-repository lessons were all
added online by earlier DeepSWE tasks. With same-repository lessons excluded
at selection time, ContextGraph still improves over no memory by 1.4, 7.3,
and 6.7 points, about half of the full gain on Related-Lite99 and DeepSWE113;
the full pool adds a further 6.2, 6.4, and 4.6 points.
\textbf{Finding:} experience from other repositories carries much of the gain,
so a shared memory across projects is worth building; lessons from the same
repository, though fewer, add the rest.

\paragraph{Benefits across language models.}
Memory methods draw from the same 300-summary pool within each backbone

and has the highest point estimate in each comparison, whereas the other
memory methods do not improve consistently (Mem0 falls below no memory on MiniMax
M2.7).

\section{Conclusion}
ContextGraph links transferable strategies and warnings to the conditions
under which they apply and to their source experience; agents select this
guidance before planning and after errors and add new experience after each
task. It improves over no memory on all three benchmarks and reaches the
highest rate among the evaluated memory methods. For those building
coding-agent memory, our results suggest four practices: store abstract
lessons with their applicability conditions rather than raw trajectories; let
the agent select them from its full context; search again after errors; and
keep adding experience from other repositories and from each completed task.
We hope the released code and pools help others extend these findings.

\section*{Limitations}
Our ablations remove abstraction and condition matching together with other
parts of the lesson; a variant that strips only the applicability condition
would pin down its contribution further. Paired per-task statistics, a
retry control in which a no-memory agent reflects on its own failures
\citep{reflexion2023}, longer task streams, and more languages and agent
scaffolds are natural next steps.
