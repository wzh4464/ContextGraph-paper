\section{Additional system comparisons}
\label{sec:historical}
These comparisons examine summary and episodic memory across models and
attempt budgets. Two configurations of ContextGraph appear in them and are
named explicitly here. The \emph{summary-memory configuration} is the
experience graph of Section~\ref{sec:method} built from an initial pool of
300 experience summaries distilled from the audited SWE-bench cold-start pool
(Appendix~\ref{sec:overlap-audit}), with the mini-SWE-agent scaffold and the
main-comparison budget; it is the Related-Lite99 run of the main comparison,
which uses the experience graph on all three benchmarks.
Figure~\ref{fig:swectx-crossmodel} and the pool-size study of
Section~\ref{sec:generalization} use it to examine other backbones and initial pool sizes. The
\emph{episodic-memory configuration} serves 291 curated repair records with
prior code history, reference fixes, and verification hints;
Table~\ref{tab:swectx-stream} and Table~\ref{tab:swectx-xmodel} use it.
Table~\ref{tab:dev50} gives an early 50-task
development comparison on SWE-bench Verified. Resolution rates are
percentages; gains marked pp are percentage-point differences from no memory.

\paragraph{Memory access and evaluation.}
The agent uses its full current context to search the experience pool,
read records, and follow links to relevant strategies. In the backbone
comparison, the Kimi K3 and MiniMax M2.7 runs use one attempt per task and
report rates over completed evaluations; MiniMax M2.7 uses an API
compatibility layer. The pool-size study varies the initial pool from 50 to
300 summaries (Section~\ref{sec:generalization}).

In the curated-episode comparison, each pass adds the distilled lessons of its
completed attempts to the pool before the next pass retries unresolved tasks
(Section~\ref{sec:stream}). Official test results are withheld
from the agent throughout, including between attempts.

\paragraph{Source-similarity sensitivity.}
A separate analysis removes ten targets whose source fixes have token-Jaccard
similarity of at least 0.85. These are distinct tasks, not target trajectories
in the memory pool. On the remaining 89 tasks, DeepSeek V4 Pro resolves
21.35\% with memory versus 14.61\% without memory ($p=.031$).
Appendix~\ref{sec:overlap-audit} applies the same criterion to every initial
pool of the main comparison.
