\section{ContextGraph: memory for planning, recovery, and learning}
\label{sec:method}
\label{sec:motivation}
\paragraph{Setting.} Tasks $q_1,\ldots,q_T$ arrive as a stream in issue
creation-time order; each gives the agent an issue and a repository, and the
agent produces a patch. Its trajectory $\tau_t$ records actions,
observations, and the outcome. Memory starts from a graph $G_0$ built from
trajectories $\mathcal D_0$ of other tasks. While solving $q_t$, the agent
selects lessons from $G_{t-1}$; afterward, ContextGraph distills $\tau_t$
into $G_t=\operatorname{Update}(G_{t-1},\tau_t)$
(Figure~\ref{fig:experience-memory}). $\mathcal D_0$ excludes the evaluated
tasks, updates use only agent-visible observations, and lessons may come from
any repository.

\subsection{Abstract experience into conditioned lessons}
\label{sec:experience-abstraction}
A language model extracts lessons from the task, actions, errors, and
outcome. Each lesson is a record
\begin{equation}
 \ell=(\kappa,\,c,\,a,\,o,\,s),\qquad \kappa\in\{\text{strategy},\text{warning}\},
 \label{eq:lesson}
\end{equation}
read as ``when $c$ holds, do $a$ (for a warning, avoid $a$) to achieve or
preserve $o$,'' where $s$ links the lesson to its source trajectory. For the
initial graph, abstraction removes repository-specific names while retaining
the decision and its condition: the failed framework setup of
Figure~\ref{fig:concept} becomes the warning not to set up the full framework
first when the failure appears without the full application. Lessons
distilled online keep the files and commands the agent used, so later tasks
in the same repository can reuse them.

Lessons live in a typed graph
\begin{equation}
 G=(V,E),\qquad E\subseteq V\times\mathcal R\times V.
 \label{eq:experience-graph}
\end{equation}
Besides lessons (strategies and warnings), $V$ holds trajectories, fragments
(action--observation segments), canonical rules (merged lessons), error
patterns, problem summaries, playbook entries (retrieval-ready lessons), and
communities of related fragments. Seven relation types in $\mathcal R$ link
lessons to their source trajectories and canonical rules, rules to the
errors they address, trajectories to their fragments and problem summaries,
and fragments to the errors they caused and to their communities. These links
keep both a reusable lesson and the observations that explain when it
applies. A snapshot built from 1,795 trajectories holds 45,115 nodes and
73,975 typed edges (Appendix Table~\ref{tab:schema}). The anonymous
repository (Section~\ref{sec:setup}) releases the extraction prompts, graph
schema, and selection code.

\subsection{Let the agent select lessons for each task}
\label{sec:experience-retrieval}
At step $i$ of task $q_t$, the agent holds its full context $C_{t,i}$: the
issue, inspected code, actions, and failures. Selection is a short decision
process run by the coding agent's own policy $\pi_\theta$:
\begin{equation}
 m_j\sim\pi_\theta(\,\cdot\mid C_{t,i},h_j),\qquad
 m_j\in\{\textsc{search}(x),\ \textsc{read}(v),\ \textsc{follow}(v,r),\ \textsc{keep}(\ell),\ \textsc{stop}\},
 \label{eq:agent-selection}
\end{equation}
where $h_j$ records the preceding memory actions and their results. Searches
with a query $x$ return ranked candidates from all of $G_{t-1}$; the agent reads source
records, follows links of type $r\in\mathcal R$, and keeps a lesson $\ell$
when its condition $c$ matches the current task and error. At
\textsc{stop}, the kept lessons form $\mathcal M_{t,i}$, so the number of
selected lessons varies by task. The agent applies them through local
reproductions, edits, and tests (Appendix~\ref{sec:agentic-retrieval}).

\subsection{Query before planning and after errors; update after every task}
\label{sec:experience-access}
\textbf{Before planning,} the agent searches with the full task context for
investigation, reproduction, and testing strategies, and for warnings about
costly approaches to avoid.
\textbf{After an error,} it adds the failed action, observed error, relevant
code, and current hypothesis to that context, searches again to revise its
diagnosis, and uses repository tools to try the next step.
\textbf{After each task,} ContextGraph distills the successful or failed
trajectory and links new lessons to existing experience, and later tasks can
select them immediately (Appendix Algorithm~\ref{alg:contextgraph}). A task late in the stream
therefore selects from a larger graph than an early one, and a retry of an
unresolved task can select the lessons distilled from its own earlier failure.
