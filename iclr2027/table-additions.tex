\section{Definitions of the green table additions}
\label{sec:table-additions}
Green entries mark additional conditions or measurements in the result tables.
Green TBD cells are results to collect; the original entries remain unchanged.

\paragraph{Retry accounting (Table~\ref{tab:swectx-v2}).}
Attempts/task is the total number of solver attempts that started, including
failed and budget-interrupted retries, divided by the number of planned tasks
in that arm's frozen manifest. Recover it from the original logs. Report the
total and denominator with the mean; an environment failure before the solver
starts does not count as an attempt. Missing logs remain unassessed.

\paragraph{Random-strategy control (Table~\ref{tab:pro50}).}
Sample from the same 3,183-strategy pool using a task-specific seed derived
from seed zero and the target ID. Match the archived FAISS arm's number of
delivered strategies, formatting, model, tools, and \$10 per-task cap on the
same 50 targets. Report completed/planned, official resolutions, the
resolved/completed rate, and total recorded cost. This tests selection against
random access to the same experience pool.

\paragraph{Graph-vector coverage (Table~\ref{tab:schema}).}
For each node label, count nodes with a stored vector of exactly 3,072 entries
in the archived graph snapshot. The total-node cell counts distinct such
nodes; the edge row is n/a because this column measures node embeddings.
Query the historical snapshot read-only; these counts do not describe the
new Qwen witness graph.

\paragraph{Cost in the new backbone comparisons
(Tables~\ref{tab:new-swectx}, \ref{tab:new-gemini}, and \ref{tab:new-codex55}).}
Tokens/task is total input plus output tokens for memory construction,
selection, and repair, divided by planned targets; cached input tokens count
once. USD/resolution includes the same model work and billed execution and
verification, divided by official resolutions. Include unsuccessful attempts
and amortize one bank build over the evaluated target list. Use the reporting
budget of the SWE-Context table and first-pass runs for Gemini and Codex.
For Gemini's token row, relative gain is the reduction
$(T_{\mathrm{none}}-T_{\mathrm{CG}})/T_{\mathrm{none}}$.
Recover the benchmark, manifest, and accounting scope before populating these
cells; the separate 236K/201K report is not assigned to Gemini without that match.

\paragraph{FAISS Flat for Codex (Table~\ref{tab:new-codex55}).}
Use the same Codex/GPT-5.5 agent, confirmed target manifest, source bank, and
total budget as the two existing arms. Deliver the same three source IDs as
ContextGraph as flat records, without graph relations or composed checks.
Report first-pass and three-attempt official resolutions with explicit task
denominators, plus first-pass token and cost measurements. Resolve the
existing 20-versus-30 sampling units from raw records before a matched run;
do not compute a paired gain from the two supplied fractions alone.

\paragraph{Outcome mapping (Table~\ref{tab:planned-sequence}).}
The new column identifies the reported outcome for each research question.
Joint, Combined, regressions, and omissions use the common behavioral suite;
Utility@3 measures selected-source utility. USD/solution and time to the
resolution threshold use the efficiency definitions already specified.
This is a definition column, not another experiment.

\paragraph{Applicability strata and controls (Table~\ref{tab:planned-applicability}).}
Separate the existing challenge set into its 60 applicable, 60 contradicted,
and 30 ambiguous planned pairs. Report the assessed count and useful
acceptance, false acceptance, or uncertain enforcement in the corresponding
stratum; rates whose reference class is absent are n/a. The aggregate row
continues to summarize the same set.
For repair, add no memory and text memory with the applicability check.
The latter supplies accepted requirements as text, with the same source IDs,
preparation, tools, and total budget, but no supplied composed checks.
Evaluate all four policies on the same private held-out suite and report
Official, Preserve, Combined, and Omission. Reuse an existing baseline only
when task IDs, repetition, starting state, and budget match this comparison.
