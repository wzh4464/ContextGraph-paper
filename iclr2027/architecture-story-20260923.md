这轮修订把论文的主要信息明确为：**ContextGraph 是构建 coding-agent memory 时值得优先考虑的架构；公开基准结果展示其优势，机制实验解释关键设计怎样帮助修复。**

## 主线

过去的修复留下需要满足的行为，以及使这些行为重要的输入条件。ContextGraph 把要求、输入、操作和结果连起来。检索选择相关经验，组合把历史条件用于当前操作，执行反馈帮助 agent 修改代码。

引言中的三个挑战、方法的三个组成部分和三个机制实验继续一一对应：

| 挑战 | 设计 | 实验留下的发现 |
|---|---|---|
| 经验丢失触发条件 | Requirement memory | 列关系与构造器信息使历史要求可以用于修复。 |
| 独立例子遗漏条件交互 | Condition composition | 联合检查发现独立例子未暴露的失败。 |
| 已知要求没有落实到代码 | Execution feedback | 具体失败反馈推动文字复查未完成的代码修改。 |

## 公开结果的表述

- Verified500：346/500（69.2%），无记忆为309/500（61.8%）；在所比较的记忆方法中最高。
- Related-Lite98：四个语言模型上，ContextGraph 均领先所评测的自动记忆方法。Oracle 保持单独含义。
- Related-Lite99：两轮达到25个解决任务，无记忆需要三轮。

各表保留原有任务、模型、记忆来源及尝试设置。研究者准备的输入、现有适配器与计划中的自动准备在设置及实现附录中明确说明。
