\title{ContextGraph: Self-Improving Coding Agents\\via Cross-Repository Experience Graphs}

\begin{abstract}
Coding agents can repeat costly debugging mistakes even when useful lessons
exist in other repositories. Reusing this experience requires extracting
transferable guidance and retrieving it when it can influence the next
decision. We propose ContextGraph, a memory graph that organizes past coding
experience into reusable strategies and warnings. The graph connects these
lessons to the problems, errors, and outcomes that explain when to use them.
Before generating a repair plan, the agent retrieves guidance on what to
investigate and which approaches to avoid. After an error, it queries memory
again with the observed failure to revise its diagnosis and next action.
This allows experience from one repository to guide problem solving in another.
On SWE-bench Verified and DeepSWE113, ContextGraph achieves 69.2\% and 72.1\%
resolution, exceeding the strongest evaluated memory baselines by 2.2 and
5.9 percentage points, respectively.
On Related-Lite99, its mean resolution rate is 36.3\%, up 14.9 percentage
points over no memory. On 20 Python tasks from LoLBench, it reaches 15.0\%
pass@1 versus 5.0\% for all baselines, and 25.0\% pass@3. Behavioral
studies further examine how agents apply retrieved guidance and use failure
observations to refine repairs.
\end{abstract}

\section{Introduction}
\begingroup
\setlength{\parindent}{1em}
\setlength{\parskip}{0pt}
Each repair produces experience in locating faults, revising code, and
checking behavior. Memory makes that experience useful on later tasks,
offering a practical route toward recursive self-improvement (RSI): agents
use past repairs to improve how they solve new problems
\citep{godelagent2025,dgm2026}.

\begin{figure}[htbp]
\centering
\includegraphics[width=\linewidth]{figures/paper_results_overview.pdf}
\caption{ContextGraph improves repair success across the evaluated settings.
(a) SWE-bench Verified500 with DeepSeek V4 Pro 0813 and mini-SWE-agent;
(b) Related-Lite99 with four language models; (c) cumulative resolutions on
Related-Lite99 with DeepSeek V4 Pro. Grey denotes no memory and orange
ContextGraph.}
\label{fig:results-overview}
\end{figure}

Recent agent-memory methods retain reflections and repair lessons
\citep{reflexion2023,expel2024} and organize this experience for reuse
\citep{reasoningbank2026,ace2026}. However, experience from another repository
must guide decisions in unfamiliar code. In a Django debugging case, an agent
without memory spent effort on setup and broad rewrites without completing
the fix. Lessons from other projects suggested isolating the failure first,
tracing the error path, and avoiding a full framework setup. The
history-informed agent followed this direction and repaired the bug.
The reusable lesson concerns how to investigate a problem; the agent still
determines the local code change.

These observations motivate organizing experience around the decisions it
can inform. We ask: \emph{Can a memory graph turn experience from different
repositories into useful guidance for planning repairs and recovering from
errors on new tasks?}

Building this memory involves three challenges. First, repair trajectories
contain repository-specific names, code, and setup steps. A transferable
lesson must retain the useful decision and the situation in which it applies.
Removing too little detail ties it to the source repository; removing too
much leaves generic advice. Second, related experiences are scattered across
tasks and repositories. Similar words can describe different problems, while
different errors can call for the same debugging strategy. Retrieval needs
the connections between problems, failed approaches, and useful actions.
Third, the guidance an agent needs changes during repair. Before planning,
it needs direction for investigation and warnings about costly approaches.
After an error, it has new evidence that can change the diagnosis. Memory
must inform both decisions using the information available at each point.

To address these challenges, we propose \textbf{ContextGraph}, a memory graph
that turns experience across repositories into guidance for new repairs
(Figure~\ref{fig:experience-memory}). To support transfer, \emph{experience
abstraction} extracts strategies and warnings from past trajectories,
recording what to do, what to avoid, and when each lesson applies. The graph
links these lessons to their source experiences, problem descriptions, and
error patterns. To find useful guidance, \emph{graph retrieval} combines
semantic relevance with these connections, allowing the agent to recover
related strategies across different repository contexts. To make guidance
available when it can change a decision, \emph{memory access} emphasizes two
points: before generating a plan and after encountering an error. The first
query uses the task description to guide investigation and approach
selection. The second adds the observed error and recent attempt to guide
diagnosis and revision. The agent interprets these lessons in the current
codebase and carries out the edits and tests.

ContextGraph reaches 69.2\% resolution on SWE-bench Verified and 72.1\% on
DeepSWE113, exceeding the strongest evaluated memory baselines by 2.2 and
5.9 percentage points, respectively. On Related-Lite99,
its mean resolution rate is 36.3\%, 14.9 points above no memory and second
to Agent KB's 38.2\% (Figure~\ref{fig:benchmark-comparison}). On 20 Python tasks
from LoLBench, ContextGraph reaches 15.0\% pass@1 versus 5.0\% for all
baselines, and 25.0\% pass@3.

\noindent The contributions are summarized as follows:
\begin{itemize}
\item We propose ContextGraph, a memory graph for reusing coding experience
across repositories. It connects abstract strategies and warnings to the
problems, errors, and outcomes that explain when the guidance is useful.
\item We integrate memory retrieval into planning and error recovery.
Task information guides the first query; observed failures guide subsequent
retrieval, helping the agent select useful actions and avoid repeating
unproductive approaches.
\item ContextGraph leads the evaluated methods on SWE-bench Verified,
DeepSWE113, and the LoLBench Python subset, and improves Related-Lite99 by
14.9 points over no memory. Case studies show how retrieved guidance changes
debugging decisions and behavioral feedback helps recover omitted requirements.
\end{itemize}

\section{Experiments}
\label{sec:experiments}
\label{sec:recorded-results}
We measure task success across benchmarks, models, memory-pool sizes, and
retries, then study how retrieved lessons and failure feedback guide repairs.

\subsection{Setup and evaluation}
\label{sec:setup}
We evaluate repository-level coding tasks from SWE-bench Verified,
SWE-ContextBench \citep{swebench2024,swecontext2026}, DeepSWE113, and
a 20-task Python subset of LoLBench \citep{lolbench2026}.
A task is resolved when its patch passes the benchmark's official tests.
Each comparison fixes its model, memory pool, and attempt budget.

The behavioral studies examine how an agent applies retrieved guidance.
They use DeepSeek V4 Pro at temperature zero and matched budgets, with
researcher-prepared examples and two adapters for constructing combined
checks. Their evaluation checks are separate from those supplied to guide
repair. Appendix~\ref{sec:development-details} gives the cases and inputs;
Appendix~\ref{sec:method-contract} gives the implementation.

\subsection{Repair effectiveness}
\label{sec:benchmark}
\label{sec:recorded-effectiveness}
Figure~\ref{fig:benchmark-comparison} compares nine methods. ContextGraph
reaches 69.2\% on Verified500 and 72.1\% on DeepSWE113, exceeding the strongest
memory baselines, ReasoningBank and Supermemory, by 2.2 and 5.9 points.
On Related-Lite99, its 36.3\% mean improves on no memory and FAISS Flat by
14.9 and 9.5 points; Agent KB leads at 38.2\%.
\textbf{Finding:} ContextGraph improves repair success on all three
benchmarks, leading the evaluated methods on Verified500 and DeepSWE113.

\paragraph{Long-horizon development.}
With Codex and GPT-5.5, we build the graph from other Python tasks and evaluate
20 LoLBench tasks. All seven memory baselines match no memory at
5.0\% pass@1; ContextGraph reaches 15.0\% pass@1 and 25.0\% pass@3
(Appendix Table~\ref{tab:new-codex55}).
\textbf{Finding:} ContextGraph leads the evaluated methods on these
long-horizon development tasks.

\subsection{Performance across models and memory-pool sizes}
\label{sec:generalization}
\label{sec:recorded-generalization}
\paragraph{Benefits across language models.}
In the Related-Lite99 single-attempt comparison, memory methods draw from the
same 300-summary pool within each model (Figure~\ref{fig:swectx-crossmodel}),
including Mem0 \citep{mem02025} and LangMem \citep{langmem2025}.
With GPT-5.4, ContextGraph resolves 34/98 tasks, compared with 21/98
without memory. The oracle is given one known related summary, bypassing
retrieval; ContextGraph can retrieve several.
\textbf{Finding:} the memory architecture benefits all four agents, with the
highest non-oracle resolution rate in each model comparison.

at every intermediate step.
\textbf{Finding:} larger pools broaden source coverage, and the largest tested
pool yields the strongest repair result.

\subsection{Repair success with repeated attempts}
\label{sec:retries}
A separate Related-Lite99 experiment uses DeepSeek V4 Pro with 500 calls and
\$30 per task in both conditions. The memory contains 291 curated repair
records with reference fixes, verification hints, and history preceding the
target code version. Each pass is a repair round; later passes retry only
unresolved tasks. ContextGraph reaches 25 resolutions
in two passes; the no-memory agent needs three
(Table~\ref{tab:swectx-stream}). Excluding ten targets with near-duplicate source
fixes retains the first-pass gain, 19/89 versus 13/89 ($p=.031$).
\textbf{Finding:} useful experience helps the agent reach successful repairs
with fewer rounds, with the largest gains in the first two passes.

\subsection{How does retrieved guidance change repair behavior?}
\label{sec:evidence}
\label{sec:recorded-interventions}
\label{sec:content}
The Django example in Section~\ref{sec:motivation} illustrates strategy
transfer. Here we examine how agents apply a retrieved behavioral requirement:
what context they need, which interactions they miss, and how feedback
changes the next edit. Figures~\ref{fig:concept} and~\ref{fig:behavior-workflow}
show the checks and workflow used for these studies.

\paragraph{Retain the context that makes advice useful.}
In four paired runs, memory helps preserve query strings, remove redundant
uniqueness while retaining primary keys, honor destination timezones, and
preserve named-tuple ranges (Table~\ref{tab:historicalrequirements}). Both
repairs in the first three pairs pass official verification.

On Django12663, both retrieved memory sets contain the relevant named-tuple
source, yet both initial repairs miss its behavior. Preserving its constructor
convention fixes named tuples while keeping ordinary subclasses working;
passing every sequence's elements as separate arguments breaks the latter
(Appendix Figure~\ref{fig:memory-content-scope}). An exact operation filter
also discards this useful source, despite its first-place similarity rank.
\textbf{Finding:} advice needs its applicability context: shared columns
and constructor conventions determine how these lessons transfer.

\paragraph{Check a historical requirement in the current workflow.}
\label{sec:composition-results}
A Django12663 repair passes the current lazy-User query and historical
named-tuple example separately, but fails their combination. The range
adapter inserts the historical type into the current query, retaining the
lazy User and nested query (Figure~\ref{fig:concept}).

Three agents start from the same unrepaired code, history, current program,
tools, and instructions (Table~\ref{tab:composedconditions}). Separate
historical checks recover both historical examples but only one of three
withheld joint queries. Composed checks recover both historical examples
and all three joint queries, while preserving ordinary subclasses.

\paragraph{Use failure observations to guide the next edit.}
\label{sec:feedback-results}
Two fresh agents revisit the failed constraint repair with the same
requirement. Textual review fixes the primary-key case but misses the ordinary
unique-field case; adding the historical check and its failures helps the
agent distinguish constraint names and fix both. On the timezone task,
further issue-based review leaves the patch unchanged, while the historical
failure leads to a revision honoring the destination timezone.

Of four fresh refinements of the Django12663 candidate, history alone passes
all seven measured conditions in one of two attempts; the joint program and
failure do so in two of two. All four pass official verification. For the
simpler redirect task, a requirement sentence already yields the same correct
implementation as requirement-plus-feedback.
\textbf{Finding:} targeted failure feedback helps agents act on a known
requirement when textual review alone leaves the defect unresolved.

\section{Discussion and related work}
\paragraph{Recursive self-improvement.}
G\"odel Agent and the Darwin G\"odel Machine modify agent code
\citep{godelagent2025,dgm2026}; RRSI constrains changes to the code that
coordinates an agent's tools and actions \citep{rrsi2026}.
AlphaEvolve uses executable evaluators to guide program evolution
\citep{alphaevolve2025}; MulVul evaluates prompt revisions across models
\citep{mulvul2026}. ContextGraph contributes reusable strategies and warnings
that let past repair experience guide planning and error recovery.

\paragraph{Learning from repair experience.}
Supermemory combines relational updates and hybrid retrieval
\citep{supermemoryreport2026}.
On SWE-ContextBench Lite99 with Claude Sonnet 4.5, no memory, Supermemory,
and oracle summaries resolve 26.26\%, 30.30\%, and 34.34\%, respectively
\citep{swecontext2026}; Appendix~\ref{sec:published-swectx} gives the settings.
SWE-Exp and ExpeRepair distill repair experience \citep{sweexp2025,experepair2026};
MemGovern and STAIR organize it as cards and plans \citep{memgovern2026,stair2026}.
MemOp optimizes memory utility, ExpGraph learns retrieval, and AdaRepair-Mem
selects experience for the repair stage
\citep{memop2026,expgraph2026,adarepairmem2026}. ContextGraph connects lessons
across repositories and retrieves them to inform planning and error recovery.

\paragraph{Organizing and managing memory.}
MemGPT manages storage, SWE-MeM compresses coding histories, and A-MEM links
memory notes \citep{memgpt2023,swemem2026,amem2025}. Zep represents temporal
facts, and HippoRAG supports associative retrieval \citep{zep2025,hipporag2024}.
ContextGraph retrieves strategies with source context and error patterns.

\paragraph{Turning experience into checks.}
RETester adapts historical bug reports into tests for refactoring engines
\citep{retester2025}. MIRA separates reusable requirements from SQL corrections,
and TRACE compiles user corrections into runtime checks
\citep{mira2026,trace2026}. Our development cases combine historical triggers
with current workflows to expose failures missed by separate checks. The
trigger and expected outcome give the agent a concrete repair objective.

\section{Conclusion}
We propose ContextGraph, an experience-graph architecture for self-improving
coding agents. It turns past trajectories into transferable strategies and
warnings linked to their source context. Graph retrieval supplies this guidance
before planning and after errors to help agents choose and revise their approach.
ContextGraph
achieves 69.2\% resolution on SWE-bench Verified and 72.1\% on DeepSWE113,
exceeding the strongest evaluated memory baselines by 2.2 and 5.9 percentage
points, respectively, and raises Related-Lite99 mean resolution from 21.4\%
to 36.3\%. On the 20-task LoLBench Python subset, pass@1 is 15.0\% versus
5.0\% for all baselines. These results establish ContextGraph as a strong starting point
for coding-agent memory that learns from past repair experience.
