\paragraph{Memory configurations.}
The earlier Verified500 system indexes trajectory fragments, rules, and communities
with dense, lexical, and graph retrieval. The Related-Lite99 system indexes
300 experience summaries with repository-filtered lookup and a memory tool.
The Related-Lite99 episodic system serves reference fixes, verification hints,
and pre-base history from 291 episodes, queried before planning and after errors.
The executable-example bank used for behavioral studies is described in
Appendix~\ref{sec:method-contract}.

\paragraph{Evaluation sets and attempts.}
Verified500 uses all 500 tasks as its denominator. In the historical
Related-Lite99 summary experiments, resolution rates use completed
evaluations in each condition. Figure~\ref{fig:swectx-crossmodel} allows
one attempt; Table~\ref{tab:swectx-v2} includes failure reruns.
The single-attempt pool-size results in Table~\ref{tab:swectx-poolsize}
are 21.88\%, 27.55\%, 26.80\%, and 34.69\% for 50, 100, 200, and
300 summaries, respectively.
The MiniMax M2.7 campaign used a
gateway-compatibility shim.

\paragraph{Related-Lite99 source content.}
The episodic campaign served static source episodes: its original online deposit
path omitted fields needed for retrieval. The historical overlap analysis
identified ten targets with near-duplicate source fixes (token-Jaccard at least
0.85); removing them gives an 89-task frame. DeepSeek V4 Pro retains a
first-pass gain of 21.35\% versus 14.61\% ($p=.031$).

\paragraph{Intervention scope.}
Content comparisons start fresh agents from the original development target;
refinement comparisons start from a common completed candidate. Additional
MySQL, named-zone, and ordinary-subclass checks were constructed after
inspecting the corresponding repairs, then applied across their comparison
group. The three-arm composition comparison holds history, the current
example and failure, tools, and instructions fixed. Two arms additionally
receive either composed checks or separate historical checks, as shown in
Table~\ref{tab:composedconditions}.

\paragraph{Operation-dependent preservation.}
In Matplotlib20826, clearing and replotting twin axes restores finite data
bounds, so failure of an isolated historical plotting example does not describe
the state after that workflow. In Django16819, canceling a same-name index
remove/add pair loses a required change of indexed column. These observations
motivate applying memory conditions along the current operation sequence.

\paragraph{Additional development outcomes.}
The closed DeepSWE Kea development
baseline passes 9/12 fail-to-pass and 139/139 pass-to-pass tests (binary reward 0).
The closed JDK5 LoLBench baseline originally submitted no artifact; a separate
no-inference recovery of its recorded patch passes 0/5 fail-to-pass and 51/51
pass-to-pass tests (binary reward 0). These are development outcomes. The
historical Verified500 table is separate from these development studies.

\paragraph{Executable-witness bank coverage.}
The archived 273-source bank provides at least one witnessed source from the
same repository for 133/150 Verified targets, 91/99 Related-Lite targets,
2/100 LoLBench targets, and 0/113 DeepSWE targets. These counts describe the
executable-witness bank used during development, rather than the
cross-repository strategy memory in the main benchmark comparison.
