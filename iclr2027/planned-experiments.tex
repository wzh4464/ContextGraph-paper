\section{Experiment 1 plan: matched repair effectiveness}
\label{sec:planned-outcomes}
These planned experiments use a common agent and DeepSeek V4 Pro backbone,
with Qwen3-Embedding-8B for new embeddings. Red TBD cells mark results still
to collect; black coverage counts are existing measurements. Each patch is
graded by its benchmark's verifier. Paired intervals resample targets while
keeping repeated attempts together. Report assessed and planned counts;
infrastructure failures remain unassessed. Cost includes preparation,
selection, checks, repair, and verification.

\paragraph{Memory settings.}
The primary comparison fixes each method's memory before target evaluation.
All methods use the same historical sources, with their own memory construction
adapted to the common agent. The same backbone performs extraction, selection,
composition, and repair. The sequential-update comparison starts from these
banks, then permits updates after submission under the same feedback and
at least three fixed task orders. Table~\ref{tab:planned-fourbench} reports
the four-benchmark comparison; Appendix~\ref{sec:public-program} describes
the shared program-preparation step.

\section{Experiment 2 plan: content and mechanism ablations}
\label{sec:planned-content}
The development panel uses 24 targets from the 70-task development partition,
covering at least four repositories and four operation families. Task/source
pairs are selected from public evidence before the new repairs are observed.
Each arm has three fresh repetitions (72 attempts), with common source IDs,
matched budgets, and balanced arm order. The evaluation suite is fixed in
advance and includes joint requirements and originally passing neighbors.
A regression means failing at least one of these neighboring checks.
All arms share program preparation; preparation and delivery failures stay
in the assigned panel. Experiments using researcher-prepared programs are
reported separately from automatic preparation.

The seven-method panel first measures Official, Joint, Preserve, and Combined
on this suite. The content, relation, composition, and retrieval studies then
vary one part of the memory interface at a time.

\subsection{Graph relations and retrieval}
\label{sec:planned-graph}

\paragraph{Relations and composition.}
Table~\ref{tab:planned-graph} uses the same 24 tasks, three repetitions, source
records, applicability decisions, check count, validator, and total budget.
B reconstructs all bindings from text; C receives the stored bindings.
D/E reconstruct only one withheld binding family. B--F share the same adapter.
G receives C's bindings but constructs a check with free-form generation.
F additionally receives execution observations before editing. All arms
retain ordinary execution tools. Explanations and tool outputs respect the
same withheld-binding masks as the memory input.

\paragraph{Separate and joint checks.}
H runs the current program plus a standalone historical check; I runs the
same current program plus a joint check. Both receive identical history,
bindings, environment, starting state, and remaining budget. Each has two
check slots, matched execution limits, feedback rounds, and observation
format. Both historical and joint checks use requirements applicable to the
current version. The independent evaluator tests both kinds of behavior on
every repair. Report Combined and the rate of repairs for which separate
checks pass but the joint check fails, using the assigned targets and their
assessment counts. This directly tests the value of combining conditions.

\section{Independent confirmation: completeness and applicability}
\label{sec:planned-independent}
The development panels select the method; the following tests establish its
scope. Their manifests, annotation rules, and endpoints are sealed before
new solver outcomes are visible. They do not reuse the 24 development tasks.

\subsection{Independent held-out behavioral completeness}
\label{sec:heldout-protocol}
After fixing the method, sample up to 40 untouched tasks per benchmark,
using a fixed seed and public repository/operation groups. Exclude tasks
previously used to develop prompts, adapters, or the method. Report the
available sample and each benchmark's number of behaviorally eligible tasks.

Two independent annotators specify requirements from the current issue,
version-matched documentation and tests, and pre-base history. They identify
current behavior, applicable historical requirements, combined triggers, and
originally passing neighbors. A third reviewer resolves disagreements;
uncertain requirements remain unassessed. The suite is sealed before new
patches are seen and kept private from the solver. Targets and expected
outcomes are selected independently of ContextGraph's retrieved or generated
checks. Programs observe meaningful behavior, such as selected rows or a
converted time.

A task is behaviorally eligible when at least one additional historical
requirement can be assessed. Combined requires official success and all
applicable joint and preservation checks on the same patch. Omission burden
counts official successes that fail an applicable requirement, divided by
eligible tasks. Report Official, Joint, Preserve, Combined, and omission
burden together, with sampled, eligible, assessed, and paired counts.
Results are separated by benchmark and repository group. First-pass patches
from the main comparison can be reused when the private suite was sealed
before those outputs and the experiment settings match.

\subsection{Applicability and harmful transfer}
\label{sec:applicability-audit}
Evaluate applicability decisions on all retrieved requirement/target pairs
in the held-out sample, including accepted, rejected, and uncertain candidates.
Independent annotators judge current validity without seeing the assessor's
decision or repair outcome.

A separate challenge set contains 60 applicable, 60 contradicted, and 30
ambiguous pairs. It covers changed APIs, incompatible types or roles,
superseded behavior, and insufficient specification. Report natural retrieval
and challenge-set results separately. False acceptance is the fraction of
contradicted requirements accepted; useful acceptance is the fraction of
applicable requirements accepted. Also report uncertain requirements enforced
and the fraction of accepted requirements that are wrong. Intervals preserve
source and target clusters.

For repair outcomes, compare applicability checking with bypassing that check
on the same eligible tasks. Hold source IDs, records, composer, check budget,
and total budget fixed. The private behavioral suite measures preservation,
Combined success, and omissions for both arms. Record assessment cost and
memory delivery alongside these outcomes.
