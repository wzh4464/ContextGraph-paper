### 对照公平性

- **冻结记忆主实验**：各方法从相同准入历史构建自己的原生记忆表示，构建后冻结。ACE 使用离线构建后的上下文；不能将这一设置描述为其完整在线系统。不同格式不强行改成同一个 payload，但要记录移植后的接口与版本。
- **顺序更新补充实验**：当前题提交后，才用允许的执行反馈更新各自记忆。独立记忆库、相同题序、相同可见反馈。不能读取未来题结果、目标 gold patch 或 withheld 行为检查。与冻结记忆分开出表。
- **辅助模型一致**：新构建、选择、组合和求解采用同一 backbone，或把差异列为独立实验。提炼和检索模型开销纳入成本，避免更强辅助模型成为隐含解释。
- **迁移口径**：在同一个 coding agent 中运行的是记录版本的适配实现。ExpeRepair 的完整修复流程不能只剩一个检索函数却仍称完整系统；改动要在配置表说明。

### 优先完成的因果对照

| 对照 | 要回答的问题 | 不能用什么代替 |
|---|---|---|
| I−H：当前＋联合检查，对当前＋独立历史检查 | 相同两次检查名额、历史信息、当前程序与反馈流程下，条件组合是否改善修复 | 增加更多检查或只选单独检查已经通过的候选 |
| r+W 对 r+H | 可执行见证是否比旧补丁提供更可靠的条件 | 两个不同来源或不同预算的运行 |
| C−B：提供绑定对文本重建绑定，使用同一 composer | 显式提供关系是否改善构造与修复 | 同时更换组合算法，或从 gate 泄露被遮蔽的绑定 |
| C−G：同一绑定，固定适配器对自由生成 composer | 组合器选择是否带来收益 | 把这个差值解释成关系信息的增益 |
| C−D、C−E：显式绑定对重建绑定 | 输入角色／操作关系是否有独立作用 | 删除关系后直接不交付任何检查 |
| F−C：预先提供同组检查的执行观察 | 提供观察是否带来额外收益；所有臂仍保有普通执行工具 | 声称完全消除了其他臂自行执行的反馈 |
| 软重排对硬匹配／FAISS | 检索是否找到有行为效用的来源 | 向量相似度、来源命中率 |
| 固定池增加干扰、固定池替换最高效用来源 | 覆盖与竞争各自的作用 | 只扩大池后宣称图更抗干扰 |

### 敏感性与统计

增加两个单因素检查：来源数量 k=1/3/5，以及记忆允许量 B0/2、B0、2B0；B0 在开发结果前选定。保持总检索加求解预算一致，记录实际交付数、完整见证拒绝、有效联合交付、Combined 与 USD。不得截断见证程序；全上下文选择器的访问范围与真正读入的内容量分别报告。

24 题的每个方法做三次独立重复。均值和样本标准差来自三个重复的任务成功率；配对区间以任务为重采样单位，保留其重复结构。多个检查不是多个独立任务。E03 的 I−H 是联合条件的主要比较；它的机制归因限于开发题，不能自动解释 E07/E15 的提升。正式集按运行前冻结的适配器支持范围分层，保留准备失败、未交付与文本回退，避免只分析成功交付检查的题。

当前程序由无记忆的共同 agent 前置阶段生成，各方法接收相同产物或失败状态，并计入各自总预算。现有公开程序片段＋手写环境封装只支持给定程序后的组合；逐目标人工准备必须标为另一个辅助设置。最终结论限定为独立检查所测得的有效要求遗漏减少。
